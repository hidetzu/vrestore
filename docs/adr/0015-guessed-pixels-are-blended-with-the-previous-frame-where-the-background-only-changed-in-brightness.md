# 0015 — 推測で埋めた画素は、見えている背景が明るさしか変わっていなければ前のフレームと混ぜる

## 決定

- 全フレームを復元するとき（`vrestore restore`、GUI の E）、前のフレームでも推測で埋めた画素（`spatial_inpainted`）を
  G_t = λ F_t + (1 − λ)(G_{t−1} + Δ) にする（`src/stabilize.zig`、λ = 0.3）
  - F_t は今のフレームで埋めた値、Δ は埋める範囲とその周り 4 px の中で見えている画素の、前のフレームからの明るさの平均の変化（R/G/B）
- 見えている画素の変化から Δ を引いた残りの絶対値の平均が 2 を超えたら（背景が動いた・場面が変わった）混ぜない
- 既定で行う。`--stable-fill off` で止められる。由来は `spatial_inpainted` のまま（推測であることは変わらない）
- GUI の R（1 フレームだけの復元）は混ぜない。前のフレームの結果を持たないため

## 理由

- 手持ちの実写の先頭（平らな灰色のフェードイン）で、埋めた面だけが細かくちらつき、利用者には「虫のようなもの」に見えた。
  フェードの分を引いたちらつきは、背景 0.01〜0.27 に対して埋めた面 0.57〜1.35（1〜11 フレーム）。
  harmonic が手がかりにする周りの画素（文字のすき間に残した画素と ROI の縁）に、文字の縁による圧縮の乱れが
  フレームごとに違って乗り、それが埋めた面に広がるためだと考える（未検証）
- 混ぜると、同じ 30 秒の先頭で、ちらつきが 1〜11 フレーム 0.67 → 0.48、1〜119 フレーム 0.47 → 0.25 になった（SPEC §4）
- 明るさの平均の変化 Δ を足すので、フェードに遅れない（埋めた面の平均の、混ぜない場合との差は最大 0.44）
- 正解のある実写 96 ケースでは、外接矩形の SSIM の差が −0.0026〜+0.0004（平均 −0.0003）で、正解との近さはほぼ変わらない

## 採らなかったもの

- **動きで運んでから混ぜる**（flow で前フレームの埋めを運び、周りとの差を harmonic で補正する）: 2026-09-27 の試作（Python、実写 96 ケース × 40 フレーム）で、SSIM 0.611 → 0.588、埋めた画素の誤差 17.83 → 18.83 と、今の方式を超えなかった。
  背景が動くときは混ぜないだけにした
- **明るさを分けずに前のフレームと平均する**（同じ試作）: SSIM 0.611 → 0.586 と正解から離れた
- **λ = 0.15**: 先頭 30 秒のちらつきは 0.25 → 0.19 とわずかに下がるだけで、実写 96 ケースでは測っていない

## 帰結

- 合成 E2E で、動かない背景では混ぜ（`restore-flat-fill` の `stable_fill.blended` = 59 / 59）、動く背景では混ぜない（`restore-pan7-fill` で 0）ことを確かめる。
  混ぜない判定を壊す（閾値を 1000 にする）と、毎フレーム別の模様の SSIM は 0.689 → 0.595 に下がった
- GUI の R で見る 1 フレームと、書き出した動画の同じフレームは、埋めた画素が少し違う
