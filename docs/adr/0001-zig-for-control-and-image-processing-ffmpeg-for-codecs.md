# 0001 — 制御と画像処理は Zig、コンテナとコーデックは FFmpeg (libav\*)

## 決定

- アプリケーション制御・ROI 検出・画像処理・背景復元・UI は Zig で書く
- demux / decode / seek / encode / remux / ピクセルフォーマット変換は FFmpeg のライブラリ
  （libavformat / libavcodec / libswscale 等）を C ABI で直接呼ぶ
- MP4 パーサ・H.264 デコーダ・音声デコーダは自前で書かない

## 理由

- 復元はフレームの画素に対する反復計算で、画素バッファを自分で持ちたい。
  `ffmpeg` プロセスを起動してパイプで受ける形だと、seek や任意フレームの再読込のたびに
  プロセスとの往復が挟まる
- Zig は C ヘッダをそのまま取り込めるので、libav\* を薄いラッパで使える
- コーデックの実装は目的ではなく、FFmpeg より正しく作れる見込みも無い

## 採らなかったもの

- **Go + `ffmpeg` プロセス実行**（姉妹プロジェクト mp4tool の構成）。
  トラック操作・再エンコードが主のツールには合うが、フレーム単位で画素を扱う本プロジェクトには合わない
- **Python + OpenCV / PyAV**。PoC には速いが、配布と実行時依存が重くなる

## 帰結

- FFmpeg の C API は版ごとに変わる。対応する FFmpeg のメジャー版は CI で固定し、変えるときは
  CI の版も一緒に上げる
- ビルドには libav\* の開発用ヘッダ・ライブラリが要る（pkg-config で見つける）
