# 0013 — 復元した動画は H.264 の MP4 に書き出し、元の音声はそのまま写す

## 決定

- `vrestore restore --out <file.mp4>` で、全フレームを復元して MP4 に書き出す（`src/mp4.zig`）。`--raw`（RGB24 の生フレーム）と併用できる
- 映像は libavcodec の H.264（libx264 があればそれ、無ければ FFmpeg にある別の H.264 エンコーダ）。既定は crf 18・preset medium、`--crf` で変える
- 各フレームの時刻は、入力のデコーダが出した pts をそのまま使う（可変フレームレートも崩さない）。分からない・戻る pts は前のフレームの 1 フレーム後にする
- RGB → YUV 4:2:0 は、入力を RGB にしたのと同じ swscale の既定で戻す。色の情報（原色・伝達特性・行列）は入力のストリームの値を写し、範囲は limited
- 音声は、入力の最良の音声ストリームのパケットを再符号化せずに写す（stream copy）。映像のパケットより前の時刻の音声を先に書いて混ぜる。
  MP4 に入らない形式なら、書き始める前に止めて `--audio none` を案内する

## 理由

- ここまでの出力は RGB24 の生フレームだけで、見るには ffmpeg で包み直す必要があり、音声も失われた。手元の動画でそのまま見比べられる形が要る
- 符号化・多重化は FFmpeg に任せる（ADR 0001）。デコードに既に libavformat / libavcodec / libswscale を使っており、依存は増えない
- 音声を再符号化しないのは、復元の対象ではない音声を劣化させないため。合成の E2E で、入力と出力の音声のパケットがバイト単位で同じことを確かめる
- 時刻を入力から写すのは、フレームを数え直すと、可変フレームレートの動画や先頭が 0 でない動画で音声とずれるため

## 採らなかったもの

- **ffmpeg コマンドを子プロセスで呼んで包む**: パイプの扱いと、実行環境に ffmpeg コマンドがあることに依存する。ライブラリは既にリンクしている
- **音声を AAC に再符号化して、どんな形式でも入れる**: 音声を劣化させる。入らない形式は少ないので、止めて利用者に選ばせる
- **映像のコーデック・コンテナの選択肢**: 使い道が決まってから足す

## 帰結

- libx264 を持つ FFmpeg が要る（Homebrew と Ubuntu の FFmpeg は持っている）。libx264 は GPL なので、それを含めて配布するときはライセンスに注意する（vrestore 自体は動的にリンクするだけ）
- 1 フレームごとに符号化の時間が足される（640x360・preset medium で 1 フレーム約 20 ms、手元の測定。並行して別の処理が走っていたので目安）
- 字幕・データ・2 本目以降の音声は写さない
