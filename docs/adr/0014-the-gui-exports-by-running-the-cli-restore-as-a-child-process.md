# 0014 — GUI の書き出しは、CLI の restore を子プロセスとして動かす

ADR 0004（GUI は検出の入口を呼ぶだけ）の境界を、書き出しの分だけ広げる。

## 決定

- GUI の E で、検出した ROI と今の設定（M / F / K）のまま、全フレームを MP4 に書き出す（ADR 0013 と同じ `vrestore restore --out`）
- 書き出しは、GUI と同じディレクトリにある `vrestore`（`--vrestore` で指定もできる）を子プロセスとして動かす。GUI の中では復元のループを回さない
- 出力は元の動画の隣に `<名前>-restored.mp4`。既にあれば `-2`、`-3` … を足し、上書きしない。
  検出した ROI を `<名前>-restored.roi.json`（detect-roi と同じ形）、集計を `.json`、標準エラーを `.log` に残す
- 進み具合は、子プロセスが `--progress` のファイルに 15 フレームごとに書き直し、GUI が 0.5 秒ごとに読んでパネルに出す（割合と残り時間の見込み）。
  終わったかどうかは `waitpid(WNOHANG)` で見る（GUI を止めない）
- X で止める。書き出しの途中で窓を閉じても止める。どちらも書きかけの MP4 は消す（再生できないため）。失敗したときも消し、ログは残す
- 判断の部分（出力の名前・子プロセスの引数・進み具合の読み取り・残り時間）は SDL に依存しない `src/export_job.zig` に置き、ユニットテストする。
  画面なしで同じ経路を通す `vrestore-gui --detect-and-exit --export <out.mp4>` を E2E にする

## 理由

- 1 時間を超える動画の書き出しは数時間かかる（ADR 0013 の測定で約 14 fps）。GUI の描画ループの中で回すと画面が止まる
- 子プロセスにすれば、GUI にスレッドを持ち込まずに済む（CLAUDE.md §3）。書き出しは CLI と同じ経路なので、CLI の E2E がそのまま GUI の書き出しの中身を検査する
- 検出した ROI をファイルに残すのは、同じ範囲で後から CLI で書き出し直したり、設定を変えて比べたりできるようにするため

## 採らなかったもの

- **GUI の中でスレッドを立てて書き出す**: 描画と復元が同じデコーダ・メモリを触らないように分ける手間がかかり、CLAUDE.md §3 のとおりスレッド化の前に ADR が要る。子プロセスの方が境界が簡単
- **標準エラーのパイプで進み具合を受け取る**: 読むたびに止まらないよう非同期の読み取りが要る。ファイルを読み直す方が簡単で、0.5 秒ごとなら負荷も小さい

## 帰結

- `zig build gui` は `vrestore` も入れる
- 止める・窓を閉じる経路は、自動の検査が無い（手元での確認だけ）
- 子プロセスの進み具合のファイルが古いまま残る（GUI が異常終了したとき）ことがある。次の書き出しの前に消す
