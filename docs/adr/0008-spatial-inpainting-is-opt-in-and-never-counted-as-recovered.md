# 0008 — Spatial Inpainting は明示したときだけ行い、「戻せた」には数えない

## 決定

- どの方式でも戻せなかった画素（由来 `unrecovered`）を、周囲の見えている画素から推測して埋める
  Spatial Inpainting を入れる（`src/spatial.zig`、`vrestore restore --fill`、GUI は F）
- 方式は 2 つ:
  - `directional`: 上下左右へ進んで最初に当たる見えている画素を、距離の逆数で混ぜる（FFmpeg の delogo、
    mp4tool の inpaintBorder と同じ考え方）
  - `harmonic`: directional を初期値に、見えている画素を境界条件にしてラプラス方程式を反復（300 回）で解く
- 手がかりにするのは ROI の外の画素（`original`）と、Temporal で戻した実画素（`temporal_real`）。
  埋めるのは Temporal の後に残った画素だけで、Temporal で戻した画素は変えない
- 埋めた画素の由来は `spatial_inpainted`（値 4）。**coverage（戻せた割合）には数えない**（ADR 0006）。
  GUI で P を押すとオレンジで見せる
- **既定は埋めない（`--fill none`）**。GUI も既定は埋めない

## 理由

- 手持ち・固定カメラの実写では、ウォーターマークの下の背景が映像の中で露出せず、Temporal ではほとんど戻らない
  （ADR 0007）。こうした動画でウォーターマークを消すには、推測で埋めるしかない
- harmonic は、実写に既知の位置へ焼き込んだ 4 つの素材（各 24 ケース）すべてで、directional と FFmpeg の delogo
  （同じ ROI）より元の動画に近い（SSIM の平均、SPEC §4）。directional は上下左右の筋が残り、harmonic は周りと
  滑らかにつながる
- 既定を「埋めない」にする理由:
  - 生成する前に、映像内の証拠から復元する（CLAUDE.md §1）。推測で埋めるのは、利用者が選んだときだけにする
  - 埋めると焼き込んだままより悪くなるケースがある: 96 ケース中 13（不透明度 0.5 で 48 中 9、1 で 48 中 4）。
    半透明のウォーターマークは下の背景が透けて残っているので、埋めるより元のままの方が近いことがある
- coverage に数えない理由: 数えると「戻せた割合」が「埋めた割合」と区別できなくなる。動かない滑らかな背景では
  埋めると SSIM 0.997 になるが、coverage は 0 のまま（映像内の証拠からは何も戻していない）

## 採らなかったもの

- **directional だけ**: 4 素材すべてで harmonic より元から遠い
- **既定で埋める**: 上の理由。オーナーが決めれば変える（そのときはこの ADR を置き換える）
- **パッチを探して貼る方式（exemplar-based）**: 画面内の別の場所の模様を持ってくるので、見た目はそれらしくなるが
  元の背景に近づくとは限らない。まず滑らかにつなぐ方式で測った

## 帰結

- 検出した ROI は参照画像の余白を含むので、本当は背景が見えている余白まで推測で埋めている。
  FFmpeg の delogo にウォーターマークぴったりの矩形を渡したもの（測定側だけが知っている位置）の方が、
  harmonic より元に近い（4 素材で SSIM 0.03〜0.08 高い）。ROI の中でウォーターマークの画素だけを見分けられれば、
  埋める範囲を減らせる（未実装）
- harmonic の反復は ROI の大きさに比例して遅い。1080p の ROI（379 x 192）でも回るが、収束しきっているかは測っていない
