# 0017 — Temporal Recovery の既定は auto にし、すべての確かめを通った画素だけを「戻した」と数える

## 決定

- `--temporal off|on|auto`（既定 auto、GUI は T で切り替え）
  - off: 別のフレームから借りない
  - on: ADR 0005 / 0007 / 0012 / 0016 のまま（周りの帯が合うフレームのうち、時間の近いものから借りる）
  - auto: on の候補のうち、次をすべて通った画素だけを `temporal_real` にする。通らなかった画素は戻せなかった扱い（`--fill` で推測で埋める）
    1. 借りる元がマスクで隠した画素・ROI の周り（ADR 0016）の外
    2. ROI の周りの帯の差の絶対値の平均 ≤ 4（on は 6）
    3. 表示中のフレームから借りる元までの、隣り合うフレームの ROI の中心の動きが、窓の中の中央値から 2 px 以内（動きが落ち着いている）
    4. 前のフレームと後のフレームの両方から候補が取れ、その差（R/G/B の最大）≤ 10。値は 2 つの平均
- `--debug <out.mp4 | dir>` で、各フレームの画素の扱いを横並びの画像に描く（`src/debug_view.zig`）
  - 左: 出力に色を重ねる（緑 = 採用、赤 = 候補はあったが auto の条件を通らず推測で埋めた、青 = 候補なしで推測で埋めた、マゼンタ = 埋めていない）
  - 右: 借りたフレーム（過去 = 青系、未来 = 橙系、遠いほど明るい）、灰色 = 不採用
- 集計の JSON に `"temporal"` と `"temporal_pixels": {"accepted", "rejected"}` を出す。provenance のファイルの形式は変えない（「不採用」は debug と集計だけ）

## 理由

- 実写では、画面全体の動き（affine）で借りた画素が正しいとは限らない。ウォーターマークの無い場所に同じ大きさの矩形を置いた疑似チェックで、
  画面の端では戻した画素の 8.0% が外れ（harmonic で埋めると 8.65%）、中央でも 1.5%。「戻した実画素は正しい」（ADR 0006）が成り立たない
- 1 枚から借りると、そのフレームで動いた被写体や、動きの推定の誤りをそのまま貼る。前後の 2 枚が同じ値を示し、動きが落ち着いているなら、
  背景の同じ点を見ている可能性が高い（前後で違う物体が写ったときに採らないことを単体テストで確かめる）
- 採らなかった画素は推測で埋め、推測だと数える（ADR 0008）。確かでない画素を「戻した」と数えるより、推測と数える方が原則に合う
- 戻す量が大きく減っても構わない（利用者の判断）。実画素を増やすのは、局所的な動き（flow）で運んで画素ごとに確かめる新しい方式の研究でやる

## 採らなかったもの

- **既定を off にする**: 合成（背景全体が動く）のように確かに戻せる素材で、auto なら外れ 0 のまま戻せる
- **on のまま、守る範囲だけを足す**: 実写の疑似チェックで外れが減らなかった（ADR 0016）

## 帰結

- 合成（crf 23）で auto は、パン coverage 0.450（on 0.968）、ROI がウォーターマークより 4 px 小さいパン 0.571（on 0.995）、遅いパン 0.028（on 0.478）、
  回転 + パン 0.116（on 0.824）。外れはどれも 0（SPEC §4）
- 実写の疑似チェック（20 クリップ・2 か所）で、auto は 1 画素も採らなかった（on は外れ 1.5〜8.0% の画素を戻していた）。
  本物の ROI の 60 秒では、ROI の画素の 0.07% を採った。実写では、別のフレームからはほぼ何も戻らない
- 動画の最初と最後のフレームは前か後ろが無いので、auto は採らない
- 既存の合成 E2E は on の仕組みを確かめるので `--temporal on` を明示し、auto・off・debug の E2E を足した
