# 0020 — 既定のマスクは gradient。帯・おとり・取りこぼした輪郭で信用できるか確かめ、駄目なら auto に戻す

ADR 0019 の `--mask gradient` を既定にする。そのために、推定した形を信用してよいかを実行時に確かめる。

## 決定

- 既定を `--mask none` から `--mask gradient` に変える
- gradient は、推定した形を次の 3 つで確かめ、どれか 1 つでも超えたら信用せず、`--mask auto`（変わりにくさ、ADR 0010 / 0011）に戻す
  1. **帯**: 範囲（ROI + 8 px）のうち ROI の外で、ウォーターマークらしい（背景の水準との差 > 24）画素の割合 > 0.2
  2. **おとり**: ROI の隣（下・上・右・左のうち画面に収まる最初の 2 か所）の同じ大きさの範囲で同じ推定をし、ROI 相当の中で取った割合 > 0.05
  3. **取りこぼし**: ROI の中の、どのフレームでも同じ輪郭（勾配の時間方向の中央値が 12 を超える画素）のうち、隠す画素に入らなかった割合 > 0.02
- ROI の中で何も際立たない / ほぼ全部（ADR 0019）も信用しない
- 集計の JSON に `mask_trust`（`reliable`、帯・取りこぼし・おとりの値、理由、実際に使ったマスク `used`）を出す
- GUI の K は gradient → auto → none の順に切り替える。GUI の R も同じ判定を通る（`restore_cmd.chooseMask`）

## 理由

- gradient は「どのフレームでも同じ勾配」をウォーターマークとするので、背景が止まっていて模様があると背景の輪郭も拾う。
  長くても変わらない（実写 A の 1 フレームを 10 分止めた 18 ケースで適合率 0.22〜0.80）。止まっていても平らな背景は拾わない
  （1080p 固定カメラの隅で適合率 0.84〜1.00）
- 拾ったかは、ウォーターマークが無いはずの所（帯・おとり）に出るかで分かる。175 ケースで、適合率 < 0.6 を当てる AUC は
  帯 0.973、おとり 0.925。前半 / 後半で推定した形の一致（IoU）は 0.488 で、当てられない（背景が止まっていても形は一致する）
- 取りこぼしの判定は、輪郭を取りこぼした場合のためのもの（単体テストで、背景の水準に近い 2 色の板の境目を取りこぼすと
  割合が上がり、信用しない）。⚠ 探索の 720p の録画の 1 ケース（帯もおとりも通ったのに入力のままより SSIM −0.143）は、
  Python の試作では割合 0.065 で捕まえたが、Zig の実装では 1 px 広げた分で輪郭が覆われ 0.0022 で、捕まえられない（帰結）
- 戻り先を auto にするのは、信用できない動画では none・auto・gradient がどれも正解の形に届かず、その中で auto が平均で上だったから
  （探索の 84 ケースを Python の試作の判定で振り分けると、判定込みの平均 SSIM: 戻り先 none 0.774、auto 0.788。常に none 0.689、
  常に auto 0.751。auto との差の最悪は、戻り先 none −0.252、auto −0.007）
- Zig の実装で探索の 84 ケースを回すと、既定（判定込み）0.786 / 26.83 dB、none 0.689 / 22.79、auto 0.751 / 25.71、正解の形 + 1 px
  0.869 / 30.51。none との差の最悪は上の 720p の録画の −0.143、それを除くと −0.023

## 確かめ（holdout2）

閾値を決めるのに使っていない 30 ケース（実写 A の 1500 / 3300 / 6200 秒から 10 分〜、止めた背景 2 種、720p の録画の右上、5 秒、
図柄 small / repeat / jp-yellow）で、SSIM / PSNR の平均: none 0.700 / 23.76、auto 0.737 / 25.56、**既定（判定込み）0.773 / 26.89**、
正解の形 + 1 px 0.823 / 29.00。none より上 21 / 30、none との差の最悪 −0.029 / −1.77 dB（5 秒のクリップで auto に戻ったもの）、
auto との差の最悪 −0.010。動きのある長い 18 ケースはすべて gradient を使い、正解の形と同程度（SSIM 0.827 と 0.823）。

## 採らなかったもの

- **戻り先を none（ROI 全体を隠す）にする**: 上の比較で、信用できない動画で auto より最大 0.252 下がった
- **前半と後半の推定の一致で確かめる**: 上（AUC 0.488）
- **取りこぼしを減らすため、輪郭（> 12）をマスクに足す**: 取りこぼしは減るが、うまくいっていたケースで適合率が 0.05〜0.08 下がった
  （6 ケースの試作）。取りこぼしの減らし方は次のループで扱う

## 帰結

- 既定で、動きのある長い動画のウォーターマークが文字の形に近く隠れ、文字の間の背景が入力のまま残る
- マスクの推定に、動画全体から 150 フレーム（gradient）を読み、信用できなければさらに 60 フレーム（auto）を読む
  （2 時間の 640x360 で gradient の推定 13 秒）
- ⚠ 残る弱点: 背景が止まり模様がある動画（画面録画・固定カメラ）、数秒の動画では auto に戻るので、そこは改善しない。
  帯もおとりも取りこぼしも通ったのに文字の外周 1 px を取りこぼす場合（探索の 720p の録画で再現率 0.86、SSIM −0.143）は、判定で
  見つけられない。取りこぼした外周が harmonic の手がかりになり、文字の形の誤差が出る。holdout2 では起きなかった。マスクの外周の
  取りこぼしを減らすのは次のループで扱う
- 既存の合成 E2E は `--mask none` を明示し、今までと同じものを確かめる。既定は `restore-cut-default` で確かめる
