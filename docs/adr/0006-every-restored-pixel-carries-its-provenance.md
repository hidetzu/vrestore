# 0006 — 復元結果の各画素は、どの方式で作られたか（provenance）を持つ

## 決定

- 復元結果の各画素に由来を 1 バイトで付ける（`src/provenance.zig`）。ファイル形式は 1 画素 1 バイト、
  フレームごとに幅 x 高さ（`vrestore restore --provenance`）

  | 値 | 名前 | 意味 |
  |---|---|---|
  | 0 | `original` | ROI の外。入力の画素そのまま（処理の対象外） |
  | 1 | `unrecovered` | ROI の中で、どの方式でも戻せなかった。入力の画素（焼かれたまま）を残している |
  | 2 | `temporal_real` | 背景が動いて見えている別フレームの実画素（ADR 0005） |
  | 3 | （予約）`alpha_recovered` | 半透明のウォーターマークを外して戻した画素 |
  | 4 | （予約）`spatial_inpainted` | 周囲から推測して埋めた画素 |

- **coverage は「映像内の証拠から戻せた割合」** で、`Provenance.isRecovered()` が true の由来だけを数える。
  予約した値のうち、`alpha_recovered` は証拠（透けて残った背景）から戻すので数える見込み、
  **`spatial_inpainted` は推測なので数えない**。分母は ROI の中の画素（`original` 以外）
- 由来ごとの性質（coverage に数えるか・ROI の中か・GUI の色）は、`Provenance` の網羅した switch に置く。
  値を足すと、コンパイラがすべての性質を決めるよう求める
- 評価（`vrestore compare --provenance`）は由来ごとに画素数・割合・PSNR・外れた画素の割合を出す。
  これまでの `masked_*` は「coverage に数える由来の画素」をまとめたもの
- 二値のマスク（戻せた = 255 / 戻せなかった = 0）はやめて、provenance に置き換える

## 理由

- 復元方式を足していくと、「戻した画素」の中に確かさの違うものが混ざる。実画素を持ってきたもの、
  半透明を外したもの、推測で埋めたものを区別できないと、coverage や PSNR が何を言っているのか分からなくなる
  （CLAUDE.md §1: 生成する前に、映像内の証拠から復元する）
- 二値のマスクと provenance を並べて持つと、同じ問い（その画素は戻せたか）に答える形が 2 つになり、
  片方だけ直すと食い違う（CLAUDE.md §3）。provenance から二値は作れるので、provenance だけを持つ

## 採らなかったもの

- **二値のマスクを残し、provenance を別に足す**: 上の通り 2 つの形が食い違う。使っていたのはこのリポジトリの
  スクリプトと CI だけなので、置き換えた
- **由来を 1 画素に複数持つ（ビットの組み合わせ）**: 1 画素の値はどれか 1 つの方式で作られる。
  「何を試して何が失敗したか」は画素ごとの情報としては要らない

## 帰結

- 置き換えの前後で、Temporal Recovery の出力と評価値は変わらない（合成 120 ケースで、coverage・SSIM・PSNR・
  戻した画素の PSNR・外れた画素の割合など 2,880 個の値が一致。SPEC §4）
- `restore --mask` と `compare --mask` は `--provenance` になった。古い二値マスクのファイルは読めない
  （255 は知らない値としてエラーになる）
- 方式を足すときは、`Provenance` に値を足し、網羅の switch を埋め、`vrestore compare --provenance` の出力に
  新しい由来が出ることを確かめる
