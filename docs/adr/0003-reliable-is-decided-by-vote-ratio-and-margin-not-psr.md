# 0003 — reliable は得票率と margin で決め、PSR は使わない

⚠ **状態: 暫定。** 判定方式はオーナーが見直し中。結論が出たらこの ADR を確定するか、置き換える。
それまでの実装はここに書いた判定で動く。

## 決定

ROI 検出の `reliable` は、

```text
confidence（最頻位置の得票率） >= 0.4  かつ  margin（最良位置と、それ以外で最も良い位置の相関の差） >= 0.08
```

で決める。PSR は JSON に出すが判定には使わない（`--min-psr` で明示したときだけ使う）。

## 経緯

初期構築時の方針は「得票率 + PSR。PSR 単独では決めない」だった。

## 理由

- 繰り返す文字列の途中を切った参照画像では、**得票率 1.000・PSR 20 台のまま別の行に当たる**ケースが出る
  （SPEC §4）。外れたケースの PSR は 4.1〜23.3、正しいケース（繰り返し以外）の PSR は 4.2〜20.2 で、
  範囲が重なる。得票率と PSR の閾値をどう組み合わせても、「位置が違うのに reliable=true」を 0 にできなかった
- PSR はピーク近傍を除いた相関の分布全体に対する突出度なので、競合する位置が 1 か所増えても
  ほとんど動かない（同じ模様を 2 か所に置くと 12.11 → 11.79）。margin は 2 番手との差なので 0 になる
  （0.749 → 0.000）。「似た場所が他にある」を捕まえられるのは margin の方
- PSR の絶対値は探索したピラミッドの階層の解像度で変わる（mp4tool での観測）。margin は相関の差なので
  [-1, 1] の尺度が保たれる
- 実写（固定カメラの 1920x1080 の映像に既知の位置へ焼き込んだもの）でも同じ形が出た。繰り返す文字列の
  一部を切った参照が隣の語に当たり（dx=390）、得票率 0.600・PSR 14.9 のまま margin 0.043 で止まった。
  同じ実写の結果（位置が正しかった 371 件。焼き込んだ 354 件と、焼き込まない動画で静止した背景を
  正しく見つけた 17 件）で、得票率 + PSR で位置違いの reliable を 0 にするには得票率 ≥ 0.65 が要り、
  そのとき誤棄却 20/371。得票率 0.4 + margin 0.08 では 26/371（うち焼き込んだものは 22/354、SPEC §4）。
  この素材に限れば得票率を上げるだけでも止まる
- 得票率は、ウォーターマークの無い動画（背景が動く）を捕まえる。そのときの得票率は 1/15 で、
  margin は 0.74 まで高くなることがあるので、margin だけでは足りない

## 採らなかったもの

- **得票率 + PSR**（当初の方針）。上の通り、較正の素材で安全側に倒せなかった
- **3 つすべて**。PSR の下限を足しても、較正の素材では得票率 + margin より良くならなかった
  （棄却が増えるだけ）

## 帰結

- 閾値を変えるときは `scripts/roi-calibrate.sh` で較正をやり直し、SPEC §4 を更新する
- 閾値 0.08 は mp4tool で別の合成素材から較正された値で、ここでは独立した素材で測り直して変えていない。
  境界の余裕（外れたケースの margin 最大 0.021、正しいケースの最小 0.112）は合成素材でのもので、
  実素材では測っていない
