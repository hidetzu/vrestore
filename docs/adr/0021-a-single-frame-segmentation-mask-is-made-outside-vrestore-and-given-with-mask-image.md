# 0021 — 1 枚のフレームからのマスク（MobileSAM）は vrestore の外で作り、--mask-image で渡す

ADR 0020 で、gradient の形を信用できない動画（背景が止まっていて模様がある、数秒しかない）は --mask auto に戻すことにした。
そこでも正解の形との差が残る。それを埋めるマスクを、vrestore の実行時の依存を増やさずに使えるようにする。

## 決定

- `scripts/sam-mask.py`: 先頭から 75 フレーム目を読み、ROI の周り 64 px を切り出し、ROI を箱として MobileSAM（Apache-2.0、重み 40.7 MB）に
  与え、評価値が最も高い候補のマスクを 1 px 広げ、ROI の周り 8 px の外を捨てて、動画と同じ大きさの画像に書く。
  `vrestore restore --mask-image` にそのまま渡す
- vrestore 本体は、gradient を信用できなかったとき、理由と一緒にこのスクリプトを標準エラーで案内する。自動では呼ばない
- MobileSAM・PyTorch は vrestore の実行時の依存にしない。スクリプトは CI で回さない

## 理由

- 止まった模様の背景では時間方向の手がかりが無く、映像の中の証拠からはマスクを作れない（ADR 0020）。1 枚の画像の見た目から切る
  モデルなら作れる。マスクは「どこを置き換えるか」を決めるだけで、埋めるのは今までどおり harmonic（推測は spatial_inpainted、
  ADR 0005 / 0008）
- 探索（止まった背景の 33 ケース。固定カメラ全体 9、止めた背景 24）: 既定（gradient → 信用できなければ auto）0.712 / 25.69 dB、
  MobileSAM のマスク 0.837 / 30.00、正解の形 + 1 px 0.879。マスクの適合率 0.52 → 0.88、再現率 0.985 → 0.990、IoU 0.83。
  gradient を信用できたケースは gradient のまま、それ以外を MobileSAM にすると 0.839、上 24 / 下 5、最悪 −0.016
- 確かめ（holdout2 のうち gradient を信用できなかった 12 ケース。止めた背景 6、720p の録画 3、5 秒 3）: 0.692 / 22.27 → 0.799 / 26.41、
  正解の形 0.823。12 / 12 で上、最悪 +0.012。適合率 0.48 → 0.93
- 実写 A に元から焼かれた縁取り付きの文字（正解なし）でも、gradient（2 時間全体から）と重なった（MobileSAM 7,533 画素、gradient 6,992、
  両方 6,886）
- 本体に入れる（ONNX Runtime を C API で呼ぶ）と、実行時の依存とモデルの置き場所が増える（CLAUDE.md §3）。まず外で使い勝手を見る

## 採らなかったもの

- **学習済みの透かし除去モデル（WDNet・SplitNet・SLBR・DENet）**: リポジトリにライセンスが無く、依存にも同梱にもできない
- **Hi-SAM（文字用の SAM）**: 重みのライセンス表記が無く、学習データの一部（TextSeg）が商用不可
- **本体への組み込み（ONNX Runtime、ビルドのときに選ぶ形を含む）**: 外のスクリプトで使い勝手を見てから決める

## 帰結

- 背景が止まった動画でも、2 段（スクリプト → `--mask-image`）でマスクを正解の形に近づけられる
- 1 フレームの推論は CPU（Apple M2 Max の Rosetta 上の x86_64）で 0.9〜1.6 秒
- ⚠ 使うフレームは 1 枚（75 枚目）。その時点でウォーターマークの周りが他の物と紛らわしいと外れうる。複数のフレームで決める方式は測っていない
- ⚠ 固定カメラ全体の 9 ケースでは、gradient を信用できたケースで MobileSAM の方が下がった（最悪 −0.076）。信用できたときは gradient を使う
