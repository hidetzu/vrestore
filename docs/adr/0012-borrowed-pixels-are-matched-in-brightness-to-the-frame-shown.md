# 0012 — 別のフレームから借りた画素は、表示中のフレームの明るさに合わせる

## 決定

- Temporal Recovery で別のフレーム s から画素を借りるとき、ROI のすぐ外側の帯（幅 6 px、今も移動の確かめに使っている所）で
  「表示中 − s」の差を R/G/B ごとに平均し、借りた画素に足す（`src/temporal.zig` の `recoverFrame`、`ringDiff`）
- 由来は `temporal_real` のまま。形（どの画素がどんな模様か）は s の実画素で、足すのはフレーム全体の明るさの差だけ
- 帯の確認（差の絶対値の平均 ≤ 6）は変えない。明るさの差もこの確認に含まれるので、大きく明るさの違うフレームからは借りない

## 理由

- 露出や圧縮の違いで、借りた画素だけわずかに明るい / 暗いことがある。手持ちの実写に焼いた 1 ケースで、ROI の下端に沿って
  別フレームから戻した 3 行が正解より +2.2 / +1.2 / +0.3 明るく、線に見えた（入力のその行は正解と差 0.0）
- 合わせると、戻した画素の誤差の絶対値の平均が 3.15 → 2.31 になった（SPEC §4）
- 帯は、借りる前に移動が合っているかを確かめるために既に比べている所なので、足す計算はほぼ増えない

## 採らなかったもの

- **Poisson 合成（勾配だけを借りて、境界で周りに合わせる）**: 場所ごとの差にも合わせられるが、フレームごとに方程式を解く。
  今回見えた段差はフレーム全体の明るさの差で説明できたので、まず平均の差だけにした
- **帯の確認から明るさの差を除く**: 明るさが大きく違うフレームも使えるようになるが、確かめる基準が変わる。今回は変えない

## 帰結

- 合成の動画は明るさが変わらないので、合成 E2E の数値はほぼ変わらない（差 0.001 以内）
- 明るさの差が帯と ROI の中で違う（光が場所によって変わる）と、合わせきれない
